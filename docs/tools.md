# Инструменты и планирование

## Команды

| Tool                       | Назначение                                                          |
| -------------------------- | ------------------------------------------------------------------- |
| kuper_session_status       | Очередь, кэш, cooldown и последняя ошибка; не проверяет авторизацию |
| kuper_session_reset        | Закрытие HTTP-сессии и очистка кэша с сохранением cooldown          |
| kuper_list_cities          | Города из app configuration, если поле доступно                     |
| kuper_suggest_addresses    | Подсказки адресов с явным cityId                                    |
| kuper_list_stores          | Магазины по точным latitude/longitude, страницы по 24               |
| kuper_search_products      | Поиск внутри storeId, сортировка и пагинация                        |
| kuper_search_city_products | Поиск в 1–5 магазинах для адреса, с признаком truncation            |
| kuper_compare_products     | Отдельные сравнения ₽/кг, ₽/л и ₽/шт по переданным снимкам          |
| kuper_list_recipes         | Стартовые рецепты с фильтром кухни и диеты                          |
| kuper_match_ingredients    | До 30 запросов ингредиентов, кандидаты для проверки                 |
| kuper_plan_week            | Меню по снимкам товаров, без проверки актуальных цен                |
| kuper_plan_week_live       | Меню после загрузки цен выбранных товаров                           |
| kuper_build_shopping_list  | Суммирование ингредиентов, упаковки, стоимость и остатки            |

Ресурс: kuper://recipes. Prompt: plan_weekly_menu, аргумент request.

## Сценарий меню

1. Уточните город и **точный адрес/координаты доставки**. Центр города не гарантирует доставку в нужный район.
2. Вызовите kuper_list_stores и выберите storeId. ID передаются строками, чтобы не терять точность больших чисел.
3. Получите рецепты через kuper_list_recipes или подготовьте свои. Передавайте один и тот же массив рецептов при подборе и планировании. Все количества и БЖУ — на одну порцию.
4. Соберите уникальные ингредиенты {id, query, unit} и передайте в kuper_match_ingredients. Единицы: g, ml, piece.
5. Проверьте, что кандидат действительно подходит ингредиенту и его масса указана на нужной основе: масса консервов может включать жидкость. Выберите productId и составьте bindings.
6. Вызовите kuper_plan_week_live. Он ищет выбранные ID на **первой странице** запросов; если товар пропал или находится глубже, вернёт PRODUCT_NOT_FOUND. Цены могут поступить из кэша до 5 минут; TTL можно уменьшить или отключить.
7. Покажите меню и покупки с учётом constraintsMet, предупреждений и времени снимков цен.

Пример параметров kuper_plan_week_live: ID — иллюстрация, замените найденными. Bindings должны покрывать все ингредиенты выбранных рецептов; один рис не достаточен для полной недели.

```json
{
  "storeId": "327",
  "bindings": [{ "ingredientId": "rice", "query": "рис", "productId": "39055067663" }],
  "options": {
    "days": 7,
    "people": 2,
    "budgetRub": 7000,
    "dailyKcal": 2000,
    "calorieTolerance": 0.1,
    "diet": "any",
    "excludeAllergens": ["soy"],
    "maxCookingMinutes": 45,
    "minProteinGrams": 90,
    "maxRecipeRepeats": 3,
    "deliveryReserveRub": 400
  }
}
```

Кухни стартовой библиотеки: russian, italian, asian, international. Для строгого выбора кухни или vegan-меню на неделю может не хватить рецептов: добавьте свои либо явно разрешите больше повторов. Исключения ингредиентов сравниваются с ID и точным названием; категории вроде «вся рыба» нужно раскрыть в конкретные ингредиенты. Аллергены — теги рецептов milk, gluten, soy; состав выбранных товаров проверяется отдельно.

### Результаты планирования

- **feasible**: все проверяемые ограничения выполнены по переданным данным.
- **constraints_not_met**: ограниченный поиск не нашёл подходящего меню; это не доказательство невозможности.
- **insufficient_data**: не хватает полностью оценённых рецептов для каждого приёма пищи.

Три приёма пищи в день: 25%/40%/35% целевых калорий. Размер порции масштабируется в диапазоне 0.5–2; в ответе указывается portionsPerPerson. БЖУ и калории — на человека, покупки — на всех. maxCookingMinutes ограничивает время одного блюда. Beam width 48, оптимальность не гарантируется.

Калории и БЖУ рецептов **оценочные**. Скрапер не выдумывает отсутствующее КБЖУ товара: nutritionPer100=null. Неизвестные цена, наличие и упаковка не считаются нулевыми. Такие товары, а также весовые товары per_kilo без известных шагов покупки, не используются в меню. При неполном списке покупок complete=false, а totalRub — только сумма известных позиций.

Бюджет считает покупаемые упаковки и заданный резерв доставки. Доставка, сборы, минимальный заказ, акции и доступность слота требуют проверки на сайте. Для снимков из нескольких магазинов резерв должен покрывать каждый магазин. Продукты из кладовой пока не учитываются.
