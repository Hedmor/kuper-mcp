# Настройки и диагностика

## Переменные окружения

| Переменная            | По умолчанию | Диапазон / назначение                                  |
| --------------------- | ------------ | ------------------------------------------------------ |
| KUPER_MIN_INTERVAL_MS | 1500         | 1000–60000 мс между запросами                          |
| KUPER_CACHE_TTL_MS    | 300000       | 0–3600000 мс; 0 отключает повторное использование кэша |
| KUPER_TIMEOUT_MS      | 30000        | 1000–60000 мс, таймаут HTTPcloak                       |
| KUPER_SMOKE_LAT       | —            | Широта точного адреса, только для scrape:smoke         |
| KUPER_SMOKE_LON       | —            | Долгота точного адреса, только для scrape:smoke        |

Launcher загружает .env из корня проекта; контейнер получает настройки через `docker run -e`,
`--env-file` либо Compose. Запуск собранного `apps/mcp/dist/index.js` напрямую сам .env не читает.

```sh
docker run --rm --init -i --env-file .env kuper-mcp:local
```

Браузерные профили и выбор транспорта удалены. HTTPcloak — единственный транспорт.
Старые KUPER_TRANSPORT, KUPER_HEADLESS, KUPER_PROFILE_DIR, KUPER_BROWSER_CHANNEL и
KUPER_STARTUP_WAIT_MS больше не используются: удалите их из конфигурации клиента.

## HTTP-транспорт

Одна HTTP-сессия, последовательная очередь и максимум 16 разных ожидающих запросов.
Одинаковые запросы объединяются, кэш хранит до 256 ответов с исходным временем снимка.
Доступны только фиксированные маршруты каталога; внешние URL не принимаются.
Ответ ограничен 2 MiB. Сайт не обходится постранично автоматически.

Для 5xx и таймаутов выполняется до трёх попыток с увеличением паузы.
429 запускает cooldown по Retry-After; до его окончания запросы не отправляются.
401/403, неожиданные перенаправления и HTML вместо JSON возвращаются как ошибка доступа.
Автоматического решения проверок сайта или ротации прокси нет.

## Ошибки

| Код               | Значение и действие                                                              |
| ----------------- | -------------------------------------------------------------------------------- |
| INVALID_CONFIG    | Проверьте диапазоны переменных окружения                                         |
| SCHEMA_CHANGED    | Ответ API не соответствует схеме; для городов используйте проверенные координаты |
| SESSION_REQUIRED  | Купер отказал сессии или вернул проверку сайта; проверьте сеть и повторите позже |
| RATE_LIMITED      | Дождитесь retryAfterMs; сброс сессии не отменяет cooldown                        |
| NETWORK_TIMEOUT   | Запрос не уложился в таймаут                                                     |
| HTTP_CLIENT_ERROR | Проверьте установку HTTPcloak и совместимость нативной библиотеки                |
| PRODUCT_NOT_FOUND | Выбранного ID нет на первой странице запроса; обновите привязку                  |
| BUSY              | Дождитесь завершения ожидающих запросов                                          |

kuper_session_status показывает очередь, кэш, cooldown, lastError и sessionBlocked.
Это локальная диагностика: отсутствие ошибки не доказывает доступ к каталогу.
kuper_session_reset закрывает HTTP-сессию и очищает кэш; новый запрос создаёт сессию заново.
Сброс не выполняется при ожидающих запросах и сохраняет ограничения частоты.

## Docker и автономный запуск

Образ использует Debian/glibc и Node.js 22. Он не включает браузер, Python, исходники,
тесты и devDependencies. Установка требует интернета при сборке; готовый образ
не обращается к npm registry при запуске. Живой каталог требует сети, а офлайн-планирование
работает по переданным снимкам товаров.

Compose запускает один HTTP-сервис: `docker compose up -d --build`.
В конфигурации MCP-клиента задайте `url = "http://127.0.0.1:8815/mcp"` вместо `command` и `args`.
Порт доступен только с локального компьютера; разные клиенты разделяют очередь и кэш.
`docker compose down` останавливает сервис. Режим stdio через `docker run --rm --init -i`
сохраняется для клиентов без HTTP, но создаёт отдельный контейнер на подключение.

### Диагностика живого каталога

```sh
docker compose exec -e KUPER_SMOKE_STORE_ID=135331 kuper node scripts/diagnose-catalog.mjs
```

Скрипт выводит HTTP-статусы, тип ответа и число товаров без cookies и полного тела ответа.
Для проверки адресных магазинов задайте также `KUPER_SMOKE_LAT` и `KUPER_SMOKE_LON`.
`KUPER_SMOKE_QUERY` меняет запрос (по умолчанию «курица»). На хосте используйте
`pnpm run scrape:diagnose` с теми же переменными. HTTP 403 со страницей «Отключите VPN»
означает страницу отказа Купера, а не отсутствие товаров или зависимостей.
Она также может появляться из-за профиля HTTP-клиента: `chrome-latest` автоматически
выбирает ОС хоста. Проверка показала HTTP 403 для Linux-профиля и HTTP 200 для
Windows-профиля в одном Docker-контейнере. Транспорт явно использует
`chrome-latest-windows` на всех ОС, чтобы поведение хоста и Docker совпадало.
Это не гарантирует доступ при будущих изменениях сервиса. Сброс сессии не меняет
профиль. Не отключайте проверку TLS.

Перенос готового образа на другой компьютер:

```sh
docker save -o kuper-mcp.tar kuper-mcp:local
docker load -i kuper-mcp.tar
```

Хосту нужен Docker Engine и совместимая архитектура.
HTTPcloak публикует нативные пакеты для Linux x64 и ARM64.
Каждую нужную архитектуру проверяйте отдельной сборкой и smoke; CI проверяет Linux x64.
